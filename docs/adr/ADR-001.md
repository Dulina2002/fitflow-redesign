ADR-001: Technology Stack and System Architecture Selection for FitFlow Mobile Application Redesign
## Status
Approved

## Context
FitFlow experienced an app rating decline from 4.6 to 3.8 stars due to tedious logging, lack of workout personalization, and user retention loss. The redesign requires high cross-platform UI responsiveness, camera-based food recognition (CV), AI adaptive workout planning, and strict GDPR compliance for health data.

## Decision
We have decided to adopt a hybrid polyglot microservice architecture:
- **Frontend Client:** React Native (TypeScript) with Hermes engine and New Architecture.
- **Core Application Backend:** Node.js with NestJS for modular REST APIs and WebSockets.
- **AI & Computer Vision Microservice:** Python with FastAPI for ML workout recommendations and food image recognition.
- **Primary Data Store:** PostgreSQL with Row-Level Security (RLS) and Redis caching.
- **Real-Time & Identity:** Firebase FCM for notifications and Supabase Auth (JWT) with native OAuth.

## Decision Drivers
- High development velocity and over 85% code reuse across iOS and Android.
- Isolation of CPU-intensive ML inference pipelines from transaction-critical business logic.
- Strong ACID guarantees and database-level data isolation for sensitive user health records.
- Minimized total cost of ownership for a mid-sized engineering team.

## Consequences
- **Positive:** Rapid multi-platform feature parity, sub-second CV model responses, unified TypeScript schemas between frontend and core backend, robust RLS data privacy.
- **Negative:** Requires managing multi-service inter-process communication (REST/gRPC) and dual runtime environments (Node.js and Python) in the deployment pipeline.
